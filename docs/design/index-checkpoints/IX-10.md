## The pages

- **Overview.** Large title = the server name; the subtitle is the description (two lines at most). Under it the bar: the face
  pile and "12 members · 5 here now" (opens the people sheet) on the left, and on the right **Invite people** (the one cream
  button; gone when there is no channel to invite into), Events, Media, Notifications (the mute / mark-as-read menu) and Server
  settings (permitted). An uploaded banner shows as a 3:1 card; a server without one has none (the made-up cover is gone: the
  hue is the server's color). The widgets are one container in **two CSS columns** (`columns: 2`, balanced, one column when main
  is under 700px; empty widgets render nothing so no column is held open). "Latest" is the feed under them, as cards of the
  event-card family. **No LiveNow**: `LiveNow`, `liveNowModel`, `ServerCover`, `serverCoverModel`, `useIconTone`, `ServerHead` and
  their tests are deleted. Because nothing above shows an event under way any more, Coming up shows it first ("Happening now"),
  and the Game widget shows a live game itself (it polls the board; `liveShownElsewhere` and `useSportsGames` are gone).
  Sections enter once on mount (14px rise, fade, 480ms spring, 40ms apart; reduced motion = a 150ms fade). Nothing runs at rest (e2e).
  `presenceLine` now reads "12 members · 5 here now" (§4.1).
- **Events.** `EventList` has two variants: `page` (the Events page: the large title says "Events", the subtitle "Fuel · 2 events
  still to come", the list keeps Export and **New event** (cream)) and `settings` (default; Server settings > Events keeps its
  own heading). Each event is a card of the event-card family: calendar tile (weekday in the hue), title with its state as a
  word (Scheduled / Active / Completed / Canceled), "Tomorrow at 9:00 PM · in Lounge · 4 interested · repeats weekly", the
  description, and the actions: **I'm in** (cream; a pressed quiet "You're in" with a check once you are), the manager's Edit,
  Refresh, iCal, Start / Complete / Cancel, and Delete in the danger ink. A past event has no RSVP and is dimmed.
- **Sports, Daily word, a game (chrome only).** The page draws the large title, the toolbar's folded title and the column;
  the board, standings, puzzle and game detail keep their own CSS. A game is a pushed page: the matchup is the title, the
  toolbar has the back chevron to the board ("Back to Sports"), Esc and Alt+Left go back. The three views gained an
  `embedded` prop (see "Outside my scope").
- **Game servers.** Cards with the type's glyph, name, state in words (up is amber and live, down is the one danger ink, not
  checked yet a ring), address and type, what the instance last saw, who is on, **Connect** (Steam games) and Copy address.
  Adding and editing stays in Server settings > Add-ons ("Manage in settings", for managers). Empty, off and loading states.
- **Sports pin.** `AmbientStrip` is a 52px card (`--ix-card`, radius 20, the event shadow): label, score cluster, field strip or
  diamond and the last play in the spare width, the score-burst chip, and the tools (expand chevron, Open, unpin). Expanding
  opens the game inside the same card (its stage still uses the pre-Index `.pc-sports-pin-stage` rules, which stay in
  `sports.css`, so the markup keeps `pc-sports-pin`, `is-open` and `is-score` next to `ix-pin`). Narrow card: the one-line
  score, the way it always collapsed. `ChannelAmbient` keeps its props; **IX-15: mount it under the large title** (today
  `GuildPage` mounts it in the conversation's `notices`).
- **Onboarding gate.** A page (region "Getting started") instead of a dialog: the large title (the welcome title), the rules in a
  card with the "I have read and agree" box, the roles as lit cards, a sticky footer with the helper line, Later (only when the
  rules do not hold it) and **Complete onboarding**. It portals into `.ix-main__content` (over what the route drew), makes the
  covered content `inert` while it is up (restored when it leaves), takes focus, and Esc is Later where there is a Later.
  Outside the frame (a test) it renders inline. It does not register with the toolbar: the conversation behind keeps its
  title and tools. It is still mounted from `GuildPage` (IX-15's file) exactly as before, with the same props.
- **Missing states** (`GuildStateScreens`, `BuildingNotFound`): `EmptyPage`. "This channel is gone" with a cream **Go to general**
  (the server's default channel, else its first text channel; "Open the server" when it has none), "This server isn't yours to
  open" with "Back to your servers", "Couldn't load channels" with "Try again". The loading skeleton is static (no pulse),
  in the conversation's own geometry.
- **Server color** (`guild/ServerColorField`, in `OverviewSection`): the eleven palette swatches (the server mark's own fill, a
  check and a ring when pressed), **Automatic** (clears: `hue: null`) and **Match icon** (computes the icon's dominant hue on
  the admin's client from a 32x32 canvas read and saves the number; a gray or unreadable icon says so, saves nothing, and is
  never silently replaced). A pick saves at once through `guildStore.updateGuild(id, { hue }, scope)` (`PATCH /guilds/{id}`,
  Manage Server); the window follows the store (e2e: Fuel goes 350 -> 176 -> automatic). A matched hue that is not one of the
  eleven shows as a selected "Matched to the icon" swatch. Model: `serverColor.ts` (`dominantHue`: a 5-degree histogram weighted
  by chroma, opacity and lightness, smoothed, the peak refined over +/-20 degrees, so a red-and-blue logo is blue, not
  purple); the DOM read is `iconPixels.ts`, apart, so the math tests run without a canvas.

## Decisions and deviations

1. **Routes for Events and Game servers** are new (§8.1 lists neither); chosen to mirror Sports and Daily word. Added to `App.tsx`.
2. **The members control is the people sheet** (`toggleSheet('people')`), not the Glass popover; `ServerHead`'s popover and its
   `home/PageRow` imports are gone (IX-14 deletes `components/home`). Nothing in my files imports from `components/home` or
   `glass/places/Lead` or `glass/primitives` any more (IX-19 can delete them once the others agree).
3. **Overview actions are text chips**, not icon circles: the glyph set has no bell, picture or gear, and words need no guessing.
4. **Widget grid is CSS columns**, not a row grid: balanced columns and no holes when a widget is empty.
5. **Media widget is three across** (two rows of six pictures), because six squares in a half-width column were thumbnails.
6. `PlayerPile`, `StatusDot`, `GameKindIcon`, `CopyAddressButton` changed look everywhere they are used (the widget, the page and Server
   settings > Add-ons > Game servers).
7. `ReasonTag`, feed cards and photos use `ix-*` classes; `FeedAvatar` is an `Avatar` now (`dailyWord/ServerWordBoard` still imports it).
8. The e2e specs use `h.emit(GUILD_UPDATE)` for a banner and description: the harness's READY and guild list do not carry them.
9. The checkpoint path follows the preamble (`docs/design/index-checkpoints/IX-10.md`), not the plan's `index-ix10-checkpoint.md`.

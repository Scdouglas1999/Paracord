### The redirects (§8.1)

- **What is remembered**, in `localStorage` (`paracord:ix-last-place`, per account, validated on read): `place`
  (`people` or a server id), `path` (the channel you were on in that server) and `people` (the conversation, Friends or
  Inbox you were on in People). Written by `usePeopleMemory(!leaving)`, called once from `SidebarSlot`: it is the one
  component mounted for every place and every app route. A server is remembered only while it is in your list, so a
  stale link never becomes "where you were". Never `/app` or a bare `/app/dms` (a redirect loop).
- **`/app`** opens the remembered channel while you are still in that server, else that server's landing channel,
  else the last People item. With nothing remembered: **your first server** (else People). **`/app/dms`** opens the last
  People item while it exists (a conversation is checked against the list), else the most recent conversation, else
  Friends. Both are `LastPlaceRedirect` (`mode="app" | "dms"`), pure rule in `resolveLastPlace` (unit tested).
- **Cold launch.** The redirect asks for what it needs (`loadAllDmChannels()`, `fetchGuilds(scope)`: a request already
  under way is joined, not repeated) and **waits** until both have answered (or failed) before it calls a remembered
  server or conversation gone. It shows only a status ("Opening where you left off…" for assistive tech). It asks
  nothing and decides nothing before there is an account (`scopes.length === 0`).
- **No People flash.** `restoreLastPlace()` runs at import and seeds `useIxPlaceStore.last` with the remembered
  server, and `placeOfPath('/app')` is now `null` (it belongs to no place), so a launch at `/app` shows the server's
  sidebar from the first paint and does not slide. `placeOfPath` also maps `/app/inbox` to People.

## Decisions and deviations (read these)

1. **`/app/dms` opens the last People item first, then the most recent DM** (spec §8.1 says "the most recent DM"). IX-6's
   `PEOPLE_PATH` comment asked for exactly this ("IX-14 makes this the last People item"): clicking the dock's People
   returns you to the Friends page if that is where you were. With nothing remembered it is the spec's behavior.
2. **`/app` with no memory opens your first server**, not People: a signed-in account with servers and no memory (a new
   device) should land in a server; People/Friends is the empty-account landing.
3. **The open conversation has the hue selection** (the glide, §5.2), including Friends and Inbox. The prototype's People
   list draws none (its `.sel-bg` exists only in a server pane, so s6 shows Jeremy unselected). Held against s6 this is a
   visible difference; I kept it because an open conversation with no mark in the list is worse and §4.5's selection
   is not channel-specific. One line to remove if the owner disagrees (`SELECTED_ATTRIBUTE` on `DmRow` and `UtilityRow`).
4. **Every row in People is 54px** (a 56 pitch, the prototype's DM row), including Friends and Inbox, so the selection is
   one element moved by a translate. A server's rows are 51 (`--ix-ch-h` is overridden on `.ix-sb--people`).
5. **No presence dot on sidebar rows** (the reference s6 draws none, §6.6 lists none); presence is on Friends, the people
   sheet and the profile card.
6. **The "…" is drawn** (spec §4.1 says it opens the People menu); the prototype's People header omits it.
7. **The Inbox row's line** is the newest thing that needs you, worded as a channel line ("Maya in looking-for-group:
   need one for ranked", "Jeremy posted a video in clips"), from `GET /channels/{id}/messages/attention` (one request, the
   top item only); counts ("2 mentions · 3 unread") until it is known, "All caught up" when nothing waits. The white count
   is **mentions only**. Reminders are not counted there (the store loads when the page opens).
8. **DM previews** come from the message store when it holds the conversation's real tail (no request), else one
   `GET /channels/{id}/messages?limit=1`, and only once the row is within 240px of the viewport
   (`IntersectionObserver`; everything counts as near where there is none). An encrypted message reads "Encrypted" with a
   12px lock unless the store already decrypted it (`withLocalDecryption`), exactly as a channel row does.
9. **`useHomeMessagePreview` moved** (`git mv`) to `ix/people/useConversationPreview.ts` (renamed; added `enabled` and
   the raw `message`). The two Glass importers changed their import (`glass/places/HomePlaces.tsx`,
   `PlacesPanel.test.tsx`: one line each).
10. **Segmented control** (`ix/people/Segmented.tsx`): a tablist, one Tab stop, arrows/Home/End move and choose, the
    count is in the tab's name ("Online 3"). Used by Friends, Inbox and New message.
11. **The Inbox's data is `useUnifiedConversations`** (the model the dock already uses), so the dock's People badge,
    the sidebar and the page cannot disagree, and mutes are honored. Unlike the overlay it spans every server you are on.
12. **Search people** opens the quick switcher scoped to people (below). It has no glyph and no key hint (the prototype's
    People field is words only).

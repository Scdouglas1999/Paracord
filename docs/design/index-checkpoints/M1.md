## How the flight works (one paragraph)

On Enter, before anything is awaited, the composer emits `say:sent` with the
words and where they sit. The timeline (same frame) appends a **view-local
stand-in row** (`sending:<nonce>`, never in any store) to the rows it draws,
holds it invisible, FLIP-glides the visible rows up to make room, and flies a
**ghost bubble** from the words to the stand-in's bubble in the fixed ghost
layer. The composer hides the words, closes up, presses the capsule and
releases the send control. When the server's message arrives it takes the
stand-in's slot **on the same DOM node**; the row is revealed in the same task
the ghost is removed, at the later of "ghost landed" and "server answered".
No double, no gap, no jump, no second animation on the real row.

## Timing (pinned in `lib/motion/sendFlight.test.tsx`; do not change)

| Constant (`SEND_FLIGHT`) | Value |
|---|---|
| `duration` (whole flight, all ghost layers) | 620 ms |
| `easeX` (x: slow to leave, then across) | `cubic-bezier(0.3, 0.05, 0.2, 1)` |
| `easeY` (y and scale) | `cubic-bezier(0.22, 1, 0.36, 1)` |
| `fromScale` | 0.95 |
| `overshoot` | y -3px, scale 1.01, at 70% progress |
| `fillFrom` / `fillTo` (words become the bubble) | 0.14 / 0.22 |
| `shadowHold` (airborne shadow, then settles) | 0.40 |
| `glide` (rows making room) / `glideTrim` | `cubic-bezier(0.32, 0.72, 0, 1)` / ends 60 ms early (560 ms) |
| `releaseMs` (send control, colors only) | 420 ms |
| `correctMs` (walk to a moved row at landing) | 140 ms |
| `retireMs` (bubble let go on failure) | 160 ms |
| `RELAX_MS` (composer press, scale .992) | 300 ms |

Hook constants (`useSendFlight.ts`): near-bottom 140 px (else no flight),
at most 4 in the air, 6 s failsafe (let go, then the arrival settles in).
Composer: 4 s safety that brings the words back if a send never resolves.

Animation ids: `data-motion-recipe:send-flight` (ghost layers, walk, retire),
`data-motion-recipe:send-room` (rows gliding), `data-motion-recipe:send-release`
(send control). The e2e specs freeze and seek by these ids.

The flight is exempt from the quiet motion system's 8px / 500ms / no-overshoot
ceilings (glass-spec §9; notes in `motion-lint.mjs` and `motion-gate.spec.ts`).
It animates transform and opacity, plus `color` (the words) and
`background-color` (the send control). **IX-18: never clamp it.**

## Events (`lib/motion/bus.ts`)

- `say:sent` `{ channelId, nonce, text, replyToId?, origin: SendOrigin | null }`,
  emitted synchronously in `beginSay`, on the keystroke's frame. `origin` is
  `readSendOrigin(textarea)`: the text area's viewport box, its `padding-left`
  (where the first glyph starts) and its computed `color`. Null under reduced
  motion: the timeline then calls `onGrounded` and the arrival settles in.
- `say:settled` `{ channelId, nonce, ok }`, emitted in `handleSubmit`'s
  `finally` for every send that began a flight. `ok` is true once the outbox
  accepted it (`answer.accepted = true` right after the runtime takes the
  draft). `ok: false` lets the bubble go (it freezes and fades, rows glide back)
  and the composer brings the words back. The composer's `watchUnanswered`
  also emits `ok: false` later when the queue card (`MessagingQueuePanel`)
  starts showing that send, so card and bubble never both claim it.

## What IX-12 must keep in `MessageInput`

1. `beginSay` runs before the first `await` of a send, and only for the plain
   case: no poll or schedule composer open, action allowed, can send, **no
   staged files**, non-empty, within the length limit, not a slash command.
   Everything else takes the ordinary path with no motion.
2. The text area is the origin: keep `data-composer-input` on it (the e2e
   selector), keep its `padding-left` equal to the real inset of the first
   glyph and its `color` equal to the drawn ink. If IX-12 changes the
   capsule's padding model (three-slice open), the words must still leave from
   exactly where they were typed: check the 0 ms frame.
3. `composerShellRef` stays on the capsule element (`pressComposer`).
   `sendButtonRef` stays on the send button; `releaseSend` reads
   `--glass-fill-quiet` and `--ink-1` from the button's computed style and
   **does nothing if either is empty**. If IX-12's Index tokens replace them,
   either keep both resolvable on the button or change `releaseSend` to the
   Index tokens in the same commit (and its unit test). The button's
   accessible name stays "Send message".
4. Hiding the words: `textarea.style.opacity = '0'` and `height = 'auto'` on
   the keystroke; `bringWordsBack` fades them in on failure. The draft itself
   is never touched by the gesture.
5. `say:settled` in a `finally` for every flight; `answer.accepted` set at the
   moment the outbox takes it, not when the server answers.
6. No other animation on the capsule or textarea at send time (the old
   `liftOut` is retired; do not bring back a lift).

## What IX-11 must keep in `MessageList` (and `TimelineParts`)

1. **Draw from `drawn`.** `useSendFlight({ channelId, me, messages, scroller,
   onGrounded, measureRow, loading })` returns the messages to draw (delivered
   plus open stand-ins). Grouping, reply layout, the empty state, the
   "Delivered" receipt and the rows array are built from `drawn`, never from the
   store's `messages`. A stand-in is never marked read, reacted to, replied to,
   deleted or counted (it never reaches a store; keep it that way).
2. **Row hooks** the hook and ghost read: the row element has
   `id="msg-<message id>"` (stand-in: `msg-sending:<nonce>`) and `data-own` for
   your messages; inside it `.glass-bubble` (the landing target: its box, four
   corner radii, color and font properties are copied onto the ghost), the
   words in `.glass-bubble__text`, and a reply's chip `.glass-tl-reply` inside
   the bubble. The CSS `.glass-msg[data-flight] { visibility: hidden;
   pointer-events: none }` / `[data-flight='held'] { visibility: visible }`
   must apply to that same row element. Renaming any of these means changing
   `sendFlight.ts`, `useSendFlight.ts`, both e2e specs and the CSS together.
3. **Virtual rows**: `timelineRows` reads `.glass-timeline__content >
   (wrapper) > row`; `measureRow` must synchronously measure the row's
   `[data-index]` wrapper (`flushSync(() => virtualizer.measureElement(...))`).
   Keep both or adapt them in the hook.
4. **Same DOM node at the handoff.** Today this holds only because the
   virtualizer keys rows by index (no `getItemKey`): the delivered message lands
   at the stand-in's index. `index-send.spec.ts` asserts it (`sameNode`).
   **Known defect (pre-existing on `feat/send-flight`, not introduced by M1):**
   because of the same index keys, when the stand-in takes the typing row's
   index React reuses the bottom sentinel's node for the typing row, and the
   make-room FLIP plays it from the sentinel's box: the typing bubble slides in
   about 120-150 px from the left during the flight (measured 122 px in the
   Index frame; visible in the Glass frames too). IX-11 should key rows by
   identity, with the stand-in and its delivered message sharing one key (the
   hook knows the pairing through `matchArrivals`; a small additive export from
   `useSendFlight` such as a `rowKey(message)` is the clean way), then remove
   `test.fail()` from "make room straight down, never sideways" in
   `index-send.spec.ts`. This is a strengthening fix; it must keep `sameNode`
   green.
5. **Receipt**: `.glass-tl-receipt` with `[data-motion-receipt]` inside; the
   hook sets `data-flight-hold` on it while anything is in the air (its line is
   reserved, hidden) and fades the receipt in after the last send settles.
6. **Empty state** carries `data-timeline-empty`: the first send ghosts it out.
7. **Arrival motion for others' messages** (index-spec §5.10) must not touch
   your own rows. Your row's only landing motion is the flight; when the flight
   declines, `onGrounded` marks the nonce and the old 8px settle (`awaitingLanding`)
   runs. The delivered row must have **zero running animations** after the
   handoff (asserted in both specs).
8. The scroller (`scrollRef`) is the element the hook measures for
   near-bottom and pins to the newest message at takeoff.
9. Ghost styles (`.glass-flight*` in `glass-timeline.css`, fill
   `var(--own-bub)` + `var(--sh-content)`, shadow `var(--sh-flight)`) may move
   to `ix-timeline.css` with the rest, unchanged. If the Index own bubble uses a
   different fill token than `--own-bub`, point `.glass-flight__fill` at it so
   the ghost lands as the exact bubble (check the 620 ms frame against `after`).
